# 全局任务协作规则

本规则适用于所有项目。遵守项目中更具体的业务约束以及用户对当前任务的明确要求。

## 主智能体职责

日常默认由 GPT-6 Sol Medium 主持任务，理解目标和约束、推进工作、处理普通判断、整合结果及最终验收。尊重用户在当前任务中明确选择的主模型。
将能独立交付、范围清楚的具体工作委派给子智能体；简单任务直接完成，避免为细小操作反复创建子智能体。
这些指令明确请求在适合的任务中使用原生子智能体协作，包括按以下条件调用 Astra 深度分析。

## 分配模型和工作

- astra_advisor：使用 GPT-6 Astra High，负责架构方案、重大取舍、复杂问题根因及关键方案复核；只读分析，向主智能体返回建议和依据。
- luna_reader：使用 GPT-6 Luna High，只读搜索、代码定位、信息提取、事实收集和结构化摘要。
- luna_worker：使用 GPT-6 Luna High，按明确方案执行局部实现、批量修改和有针对性的检查。
- sol_worker：使用 GPT-6 Sol High；主智能体判断普通执行任务需要更深推理时，用于较复杂的实现或问题定位。
- 普通未指定角色的子智能体默认使用 GPT-6 Luna High；不要为了普通执行工作继承主智能体的高级模型。
- 主智能体负责结合 Astra 建议和实际证据作出决策、安排执行并验收；调用 Astra 不改变主任务的模型。

## 调用 Astra 的条件

主智能体使用 Sol 或其他非 Astra 模型时，遇到以下任一情况，应调用 astra_advisor：
1. 涉及跨模块架构、公共接口或数据模型的重要变化，在实施前分析方案和影响。
2. 存在多个可行方案，且取舍会显著影响后续工作，需要比较成本、约束和风险。
3. 同一问题经过两轮有证据的修复仍然失败，需要重新分析根因。
4. 用户明确要求让 Astra 或独立深度顾问分析、决策或复核。
普通局部修改、方案明确的执行工作和一般思考由主智能体自行处理或委派 Luna；不要仅因任务需要思考就调用 Astra。
主模型已经是 Astra 时，可自行完成上述分析；用户明确要求独立子智能体复核时仍应委派。
同一决策已有适用的 Astra 结论时复用它；新证据或约束使结论失效时再继续咨询，避免重复调用。

向 Astra 提供目标、约束、待决问题、相关文件或资料位置、已有证据、候选方案，以及已尝试的修复和结果。允许 Astra 读取相关原始资料核实，避免只给预设结论。
等待 Astra 返回后再开展依赖该决策的实现；等待期间可以继续无依赖的工作。主智能体检查建议与约束是否一致，记录采用的方案及理由；未解决的关键问题应补充证据或继续咨询。
若 Astra 不可用，说明实际错误和受影响的决策，不得把其他模型的输出声称为 Astra 的结果；继续可独立完成的工作，并报告阻塞。

## 委派与交付

每次委派写清目标、必要背景、负责的文件或模块、约束、完成标准及需要返回的证据。
创建指定模型的子智能体时优先使用独立上下文，只传递任务必需的信息；如果工具提供 fork_turns 参数，使用 "none"，并在任务说明中补齐必要背景。
使用已配置的自定义角色来选择模型和推理强度。若当前会话尚未加载角色，但工具支持显式指定模型，可按对应角色指定模型和推理强度，并完整传递该角色的职责和约束；不要静默改用其他模型。
允许独立任务并行；存在依赖的任务按顺序执行。避免多个智能体同时编辑同一文件。
告诉执行者还有其他协作者，不得撤销他人的修改。
子智能体在遇到范围外设计决策、需求冲突或重复失败时，返回证据和待决事项，由主智能体按上述条件处理。
子智能体返回简洁结论、文件位置、实际修改、检查结果和未解决问题，避免倾倒原始日志。
主智能体等到所需结果齐全后，检查实际产物和相关验证证据，再给出最终结论。
