# 主智能体工作与按需委派

[English](workflow.md) · [简体中文](workflow.zh-CN.md)

主智能体默认直接完成任务，包括查询、规划、设计、实现、调试、非 UI 测试和交付。委派的收益大于上下文传递和等待成本时，再使用子智能体。本桌面版工作流不使用 Codex CLI。

## 任务矩阵

| 情境 | 默认处理方式 | 何时委派 |
| --- | --- | --- |
| 需求、普通方案、设计或技术决定 | 主智能体 | 有适合独立完成且需要深入判断的交付物时，使用 sol_worker |
| 代码、文档或网页查询 | 主智能体 | 查询可独立进行，或大型调查会占用主上下文时，使用 luna_reader |
| 代码修改、文档、脚本、技能、MCP 或插件 | 主智能体 | 有收益时，明确有边界的工作交 luna_worker，需要深入实施判断的工作交 sol_worker |
| 架构、公共接口、数据模型或困难根因 | 主智能体 | 重大不确定性未解决或需要独立思路时咨询只读 astra_advisor，不设自动关卡 |
| 实时电脑使用、浏览器/CDP、桌面操作或 UI 证据 | luna_browser，GPT-6 Luna High | 实时操作始终委派；主智能体可以分析已保存证据 |
| 交互或视觉实现 | 主智能体 | 有帮助时委派独立实现，并使用适用设计技能 |
| 测试设计、测试代码及非 UI 测试，包括后端 E2E | 主智能体或当前实施者 | 有帮助时委派独立检查；浏览器/桌面测试的实时运行交 Luna |
| 性能、安全、并发、迁移、依赖、构建或 CI/CD | 主智能体 | 有边界的调查或具体风险可交 worker 或 reviewer |
| Git 冲突、PR 或跨仓库交付 | 主智能体 | 独立仓库工作能减少总工作量时再委派；保持授权边界 |
| 独立审查 | 按需使用 sol_reviewer | 有具体风险或用户要求时使用，不给每次修改都增加审查者 |
| 用户沟通与最终交付 | 主智能体 | 整合已委派的结果，解决缺失证据 |

这些角色是选项，不是流程顺序。任务可以完全不创建子智能体。普通 UI 故障通常由主智能体查代码并修复，Luna 复现和验证 UI；有实际需要时才增加其他角色。

## 遇到困难时

进展停滞时先识别缺少的是证据、技术思路、执行准确性还是工具权限。有帮助时委派缺失的部分。多次有证据的失败尝试是考虑新思路的理由，不代表必须按固定轮数交接。环境故障不自动触发 Astra。

Astra 提供可执行建议并保持只读。主智能体可以自行实施建议，也可以委派有边界的修改。保留仍适用的结论；仅在新证据或建议缺口需要时创建新的顾问再次咨询。主模型已经是 Astra 时，只有独立建议有用或用户要求时才再开 Astra 代理。

## 简短交接

提供目标、关键背景、负责的文件或资源和验收条件；相关时附上失败尝试或约束。每次委派新建代理并显式设置 `fork_turns: "none"`；不要省略参数或默认继承全部/部分历史，只有用户明确要求时才继承。不要求每个 worker 前面先开一个 reader。仅主智能体创建子智能体。每个文件同时只有一名写入者，保留其他协作者的修改。

返回结果、修改文件、实际检查和未解决问题。主智能体核对结果是否符合目标，不默认重做调查或整套测试。审查者可以生成报告和测试缓存，但不能为让检查通过而修改代码、断言、配置或依赖。

## 独立上下文与完成边界

代理完成并返回结果后不再分配新工作。后续由主智能体处理或新建代理。同一次未完成任务中，可以补充信息和纠偏；需求变化时及时通知受影响的运行中代理，任务失效时中断并确认现场。

委派只提供当前目标、约束、范围、验收、资料位置和相关证据，明确区分事实、假设与已废弃方案。新代理应读取当前文件或页面，不能仅依赖旧摘要。工具若不支持独立上下文，应如实报告限制。

独立上下文不隔离共享文件、权限或页面；不复用代理也不要求删除历史或成果。可以向新代理传递仍适用的结果与失败记录。完整规则见 [AGENTS.zh-CN.md](../AGENTS.zh-CN.md)。

## 实时浏览器与桌面工作

所有实时操作交给 luna_browser，包括 CDP 查询和通过 shell 包装启动的浏览器自动化。其他角色可以使用网页/文档工具、读取普通文件和日志，也可以分析已保存的截图、DOM、记录和浏览器报告。

共享浏览器、桌面或远端业务状态只指定一名操作者。交接提供 URL 或会话，接手时重新获取状态，不复用其他代理的内存句柄。操作报错后，先观察是否生效再重试。

## 配置与评估

保留六个可用助手角色；角色存在不代表必须调用。尊重用户选择的主模型和配置的助手模型。角色不可用时，仅在支持的情况下使用准确模型备用代理，否则报告能力缺口。

观察委派是否减少工作量、重复查询、等待或上下文负担，不以代理数量衡量效果。配置检查不证明运行时角色加载或工具权限；角色定义变更后使用新的桌面任务。日常工作无需填写固定评估报告。
