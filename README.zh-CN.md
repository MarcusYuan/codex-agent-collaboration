# Codex 智能体协作规则

[English](README.md) · [简体中文](README.zh-CN.md)

这是一套开源的 Codex 协作配置，用来协调主智能体与不同职责的子智能体。仓库默认展示英文 README，同时提供完整的中文说明、双语配置、[原始中文文本](docs/original-config.zh-CN.md)，以及启发本项目的[截图](assets/codex-personalization-original.png)。

> 社区项目，并非 OpenAI 官方配置。文中的模型和角色是否可用，取决于你的 Codex 环境。

## 我们想解决什么问题

多模型 Codex 环境提供了能力、速度和成本不同的选择，但光有这些模型，并不能回答：**谁负责什么、何时需要更深的分析、最终结果由谁负责？** 缺少协作约定时，高能力模型可能被用来做例行查找，重要架构决策却只经过普通处理；主智能体可能在关键取舍尚未明确时就开始实施，也可能连续修补失败后仍不重新分析根因。委派如果缺少背景、文件边界和验收要求，还会造成执行者互相覆盖、结果无人核实。

这套规则的目标，是把合适的推理能力用在合适的决策上，同时让用户的任务始终有一位明确的负责人。因此，规则同时规定默认主智能体、不同的查阅与执行角色、升级分析的触发点，以及主智能体的最终验收责任。追求的是在合理使用时间和模型能力的前提下得到可靠结果，而不是让更多智能体参与每个任务。

这些规则最初放在 Codex 个性化设置中。我们把它们开源，是为了让这套协作约定可以版本管理、公开审阅、按环境调整，并接受其他人的改进。

## 规则如何运作

| 阶段 | 责任分配 | 作用 |
| --- | --- | --- |
| 主持任务 | 通常由 Sol Medium 负责目标、约束、决策与最终验收；用户指定的主模型优先。 | 即使多个模型参与，任务仍有一位负责人。 |
| 收集与执行 | Luna 查阅资料或完成边界清楚的修改；需要更多推理的局部执行交给 Sol High。简单任务由主智能体直接完成。 | 让日常工作使用合适的角色，又避免为每个小操作委派。 |
| 升级决策 | 重要架构、公共接口或数据模型变化，影响后续工作的方案取舍，两轮有证据的修复失败，或用户明确要求时，由 Astra High 提供只读分析。 | 在依赖该决策的实施开始前，对高影响选择作独立分析。 |
| 任务交接 | 主智能体说明目标、约束、负责文件、完成标准与返回证据；工具支持时优先使用独立上下文。 | 子智能体获得足够背景，又不必继承整段历史；并行修改也有明确边界。 |
| 决策与验收 | 主智能体评估 Astra 建议、选择方案、检查实际文件和验证结果，再报告结论。 | 顾问建议和执行者总结不会代替主智能体的判断与验收。 |

例如，一个任务需要修改多个模块共用的公共接口：Luna 可以先定位影响范围，Astra 比较可行的接口方案，主智能体选定方案后再安排实施。执行者分别负责不同文件或模块并返回验证证据，最后由主智能体检查实际改动。一个简单的局部修改则通常由主智能体直接完成，无需这一整套流程。

如果指定角色不可用，智能体应如实说明限制和受影响的决策，继续可独立完成的工作；不能把其他模型的输出称为 Astra 的结论。这些是协作偏好，不会覆盖用户要求、项目约束、权限或工具的实际可用性。

## 安装方法

**选择一种语言版本即可。** `AGENTS.md` 只提供指令，不会自动创建自定义子智能体角色、授予工具权限，或改变用户为当前任务选定的模型。如果环境支持，请单独配置 `astra_advisor`、`luna_reader`、`luna_worker`、`sol_worker`；否则调整角色部分，使其符合实际可用的工具。

### 全局使用

Codex 读取 `~/.codex/AGENTS.md` 作为全局规则。如果已有该文件，请先备份并合并需要的规则，不要直接覆盖。否则，在本仓库的本地副本中运行：

```bash
mkdir -p ~/.codex
cp AGENTS.zh-CN.md ~/.codex/AGENTS.md
# 如需英文：cp AGENTS.md ~/.codex/AGENTS.md
```

如果存在 `~/.codex/AGENTS.override.md`，它会优先于全局 `AGENTS.md`。新建 Codex 任务并询问当前生效的指令文件，以检查安装结果。详见 [OpenAI 官方 AGENTS.md 文档](https://learn.chatgpt.com/docs/agent-configuration/agents-md)。

### 只在一个仓库中使用

把所选文件复制到目标仓库根目录，命名为 `AGENTS.md`。覆盖已有文件前先检查内容，并根据项目的实际约束调整。适用的全局规则可能仍会同时加载。

### Codex 个性化设置

也可以像截图那样，把所选配置粘贴到 Codex 个性化指令输入框。GitHub 上的修改**不会自动更新**该输入框或已安装的本地文件。同一作用范围尽量只维护一份生效配置，避免版本冲突。

## 兼容性

文中的 GPT-6 模型和推理强度来自原作者的使用环境。不同账户、主机或产品版本的可用能力可能不同；用户选定的主模型优先。如果顾问角色不可用，智能体应说明实际限制，继续可独立完成的工作，并指出仍被阻塞的决策。本仓库发布的是指令，不包含可执行的角色定义或安装器。

## 参与贡献
